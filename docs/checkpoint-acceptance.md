## 失败与受影响范围修复

1. 首次启动失败：原注入器在尚未初始化装载器的挂起进程中无法查找 LoadLibraryW。增加原生装载器引导线程，应用入口线程保持挂起；修改后启动通过。
2. 既有低级键盘 Hook 忽略自动化输入，阻止快捷键验收。移除该过滤，保留原有组合键和按键去重；快捷键随后正常工作。
3. 首次读取崩溃。调整设备绑定恢复顺序，并单独扣除检查点 StateBlock 自身持有的引用；后续记录显示图形恢复已完成，故障仍发生于内存回写。
4. 调试栈指向内存复制；静态 CRT 的 `.fptable` 在 PE 中带写标记，但启动后实际为只读。将 PE 区段捕获限定为当前真正可写的页面，随后跨关卡读取及后续流程通过。

修复轮次只重建必要的启动/保存/切关前置状态并处理受影响的读取路径；已通过的前端与协议测试未重跑。代理记录核心流程通过后停止重复自测，没有压力循环、哈希校验或追加全量回归。交付整理时将设备可用性查询归到渲染线程，并修正空槽/设备重置错误反馈的前端槽位标记、arena 外分配的明确错误码以及线程/超时失败收尾；未重复已通过的完整流程。
