# TimeTransle 前端视觉与交互设计

> 状态：功能交互基线已完成；表盘几何、布局和双指针语义已按参考图修订；`0.1.2` 起倍率映射改为全程统一 `45°`/八度并加入拖动中实时吸附  
> 目标平台：Windows 10/11、WebView2、React + TypeScript + Vite  
> 参考图：`500 × 513` 像素的暖金色发光时钟图  
> 本文范围：视觉结构、时钟旋钮、输入方式、状态模型、前端通信语义与动画约束

## 1. 已确认的产品决策

1. 产品形态是一个可放在桌面角落持续使用的“桌面旋钮”或“悬浮控制器”，不是应用主页、仪表盘或管理后台。
2. 原生窗口默认约 `360×360`，建议在 `320–440` 间保持近方形缩放；不提供最大化后的大屏布局，也不为了填满空间扩大窗口。
3. 时钟旋钮是界面唯一的主要视觉焦点，占可视面积约 `65%–75%`。其他控件保持低调，不堆叠侧边栏、顶部导航、数据表格、多张卡片、霓虹边框、渐变按钮或持续循环的装饰动画。
4. 当前倍率显示在时钟下方；目标程序名称与连接状态压缩为一行；暂停、恢复 `1×` 与选择进程放在底部小型工具栏；日志、详细状态、设置和错误进入抽屉或弹出面板。
5. 主界面必须在一个屏幕内完整显示且无纵向滚动。弹层可在自身内容区滚动，但关闭后必须恢复简洁的小方形控制器。
6. 参考图只用于几何与氛围参考。产品中使用 SVG 重新绘制，不直接嵌入参考图片，也不把图片裁成按钮贴图。
7. 旋钮可达范围为 `0.0625×–8.0×`，精确输入弹层可达契约下界 `0.05×`；`1.0×` 位于正上方；暂停是独立状态，不映射到 `0×`。
8. 两根正交参考指针拆成独立语义：倍率分针直接表达唯一的 `desiredSpeed`，`1.0×` 时位于 12 点；时针初始位于 3 点，并按倍率分针可见角度增量的 `1/12` 机械联动。时针只是钟表感的被动视觉反馈，不表达第二个倍率，也不可单独操作。界面必须另外显示 Hook DLL 已确认的 `appliedSpeed`，不得在确认到达前显示“已应用”。
9. 控制器与目标程序的 Hook DLL 断开连接时，失联保护值固定为初始速度 `1.0×`，并解除暂停。不得保留最后倍率，也不设置宽限期：

   - 正常断开：Controller 先发送 `RESET`，收到确认后关闭管道。
   - 异常断开：Hook DLL 检测到管道关闭后，在 DLL 内使用相同的连续重锚逻辑立即切回 `1.0×`。
   - WebView2 页面或渲染进程失效：Controller 应尝试显式 `RESET`；若随后 Controller/Hook 管道也断开，DLL 的本地失联保护仍会生效。
   - 目标进程已经退出时不存在可恢复的时间状态；前端清除目标会话并显示“目标已退出”。

10. 重新连接或 Controller 重启后，不自动重放旧的 `desiredSpeed`。新会话从 `1.0×`、未暂停状态开始，并先获取 DLL 权威状态。

失联时前端只能准确表述“已触发失联保护，目标应恢复至 1.0×”；在管道已经断开的情况下，没有 ACK 就不能把它伪装成已确认状态。重连后由 `GET_STATUS` 完成对账。

## 2. 参考图视觉结构分析

原始参考图为 `500 × 513`。图像主体接近正方形；右边和底部的细白线属于截图边界，不属于时钟图形，重绘时不保留。

主体由以下结构组成：

1. 两条完整的同心外环，在 12、3、6、9 点方向由四根短径向桥连接；圆环本身没有断口。
2. 一条完整的内环，视觉上比外环更轻。
3. 中央空心圆形轴心，类似轴承或表盘枢轴。
4. 两根从轴心伸出的正交指针，分别指向 12 点和 3 点。
5. 接近纯黑的背景，叠加暖白至淡金色的核心描边、柔光和大范围琥珀色余辉。
6. 细微、低对比度的颗粒感。颗粒不承担信息表达，也不应持续变化。

产品化时保留完整同心环、四向连接桥、中心轴、两根独立指针与暖色发光语言。倍率分针是唯一的直接操控指针并对应 `desiredSpeed`；时针只按倍率分针角度变化量的 `1/12` 被动联动，不接受命中、不映射第二套数值。`appliedSpeed` 若需要图形提示，应使用细小的外圈标记，而不是第三根完整指针。

## 3. SVG 几何基线

SVG 使用 `viewBox="0 0 512 512"`，中心点为 `(256, 256)`。以下尺寸作为首版视觉校准起点，后续可在不改变交互数学模型的前提下微调：

| 元素 | 建议几何 |
| --- | --- |
| 最外完整环 | 半径首轮约 `198`，核心描边约 `12` 个 SVG 单位 |
| 第二完整外环 | 半径首轮约 `168`，核心描边约 `8` 个 SVG 单位 |
| 完整内环 | 半径首轮约 `123`，核心描边约 `6` 个 SVG 单位 |
| 中央轴心 | 外半径约 `18–20`，内孔半径约 `7–8` |
| 倍率分针 | 从轴心指向正上方为 `0°`；长度约 `116–118`、宽约 `7` 个 SVG 单位，独立 `<g>` 旋转 |
| 联动时针 | 初始指向正右方；长度略短于倍率分针、宽约 `7` 个 SVG 单位，按分针可见角度增量的 `1/12` 更新 |
| 四处连接桥 | 位于 `0°/90°/180°/270°`；沿半径约从 `171` 延伸到 `195`，宽约 `8` 个 SVG 单位，并与两环轻微重叠 |
| 可交互命中弧 | 半径约 `174`，透明描边宽约 `44–52` |

角度约定贯穿 SVG、数学映射与测试：

- `0°` 为正上方。
- 顺时针为正。
- 有效弧为 `[-180°, +135°]`，即指针可以转到表盘正下方，但不能越过正下方继续转到另一侧。
- 不可进入的死区是 `(+135°, +180°]` 的 `45°` 楔形，位于表盘右下方；有效弧的下端点 `-180°` 与死区上端点 `+180°` 在几何上是同一方向（正下方），但只有 `-180°` 可达。

两条外环各自使用完整 `<circle>`；四根短连接桥使用明确的径向 `<path>`，并与两侧圆环核心描边稍微重叠，避免缩放或抗锯齿产生发丝缝。不能用 `stroke-dasharray` 模拟连接关系。内环也使用完整圆。倍率分针和联动时针分别位于独立 `<g>` 中，轴心位于两者上方且不参与旋转。视觉描边不得使用 `vector-effect: non-scaling-stroke` 固定为 CSS 像素；窗口缩放时线宽、半径和按钮整体保持比例。

### 3.1 色彩基线

| 用途 | 建议色值 |
| --- | --- |
| 页面背景 | `#030201` |
| 表盘附近的抬升背景 | `#090604` |
| 核心象牙白 | `#FBE4C4` |
| 柔和淡金 | `#E8BD87` |
| 远端琥珀光 | `#B86F35` |
| 次要文字 | 暖灰白，需保证可读对比度 |
| 警告 | 低饱和琥珀色，不复用主发光色作为唯一状态信号 |
| 错误 | 克制的红色，同时配合文字和图标 |

主色不应根据连接状态持续脉冲。状态变化通过明确文字、图标和有限的短暂过渡表达，避免把发光强弱当成唯一状态编码。

## 4. SVG 分层与发光

建议 SVG/页面视觉层级如下：

```text
DialAmbient
├─ 页面径向背景光
└─ 静态颗粒纹理

DialHalo
└─ 几何副本：大范围、低透明度外部光晕

DialSoftGlow
└─ 几何副本：中等宽度柔光

DialCore
├─ 两条完整外环
├─ 四根径向连接桥
├─ 完整内环
└─ 清晰核心描边

DialPointer
├─ 独立倍率分针
├─ 1/12 机械联动时针
├─ 中央轴心
└─ 可选 appliedSpeed 小标记

DialHitArea
└─ 仅覆盖有效弧的透明宽描边
```

三层光效的职责必须分离：

1. **外部光晕**：低透明度、大范围模糊，形成参考图的环境照明感。建议模糊半径约 `12–18px`、透明度约 `0.18–0.24`；不使用明显的几何向下平移，也不随拖动实时变化。
2. **柔光层**：中等模糊和较窄描边，建议模糊半径约 `4–6px`、透明度约 `0.28–0.38`，负责让核心线条与背景自然衔接，同时必须保留双外环之间清楚的暗缝。
3. **核心描边**：不模糊或只带极轻微阴影，保证高 DPI 下仍然清晰。

静态颗粒使用一张很小的预生成无缝纹理或固定的数据纹理，以极低透明度平铺。不要运行实时 `feTurbulence`，不要动画滤镜参数，也不要在拖动时改变大范围模糊表面。

### 4.1 性能约束

- 拖动热路径只改变倍率分针 `<g>` 的完整 SVG `transform="rotate(… 256 256)"`，并在同一帧以角度增量 `1/12` 更新联动时针 `<g>`；必要时改变小范围 `opacity`。不要使用会拆成多个 CSS 分量的 `x`/`y`/`rotate` 简写。
- 不在 `pointermove` 中改变 SVG 路径、滤镜、阴影半径、描边宽度或整页背景。
- SVG 滤镜使用受控的 filter region，避免默认生成过大的离屏表面。
- 指针变化不应使整个 React 页面每次重新渲染。使用 DOM ref、独立 MotionValue 或等价局部通道，直接更新该 `<g>` 的 transform 属性。
- 在 `pointerdown` 时获取并缓存坐标变换；仅在窗口尺寸、DPI 或布局变化后重新计算，不在每次移动中反复查询布局。
- 生产构建应在 100%、150%、200% Windows 缩放下验证；SVG 必须保持清晰且不裁切光晕。
- 不设置永久性的全页面 `will-change`。如确有需要，只在交互期间对指针层短暂启用。

## 5. 页面布局

整体布局保持单焦点、低信息噪声：

```text
顶部
├─ TimeTransle
├─ Controller 状态
└─ Hook 状态

中央
├─ 大型发光时钟旋钮
├─ 目标倍率 desiredSpeed（主要读数）
└─ 已应用倍率 appliedSpeed / 同步状态（次要读数）

底部控制区
├─ 选择目标进程
├─ 暂停 / 继续
├─ 恢复 1.0×
├─ 精确倍率输入
├─ 当前程序名称与 PID
└─ 错误及警告入口
```

表盘视觉层和倍率读数必须处于两个独立网格行：`minmax(0, 1fr) auto`，建议间距约 `6px`。禁止使用负 `margin-top` 把倍率推入 SVG。表盘必须根据中央剩余高度收缩，而不是依赖裁切或重叠塞进 `360×360`。

当 `desiredSpeed === appliedSpeed` 且模式一致时，可将“已应用”状态压缩为一个安静的确认标记；不同步时必须同时展示两者，例如：

```text
目标：0.73×
已应用：0.50× · 正在应用
```

旋钮指针跟随 `desiredSpeed`。如需帮助用户理解延迟，可在有效弧上显示一个尺寸很小、亮度较低的 `appliedSpeed` 标记；同步后该标记淡出或与指针合并，不增加第二根发光指针。

## 6. 倍率与角度映射

`0.05×–8.0×` 跨度过大，不能使用线性映射。采用以 `1.0×` 为中心、**全程斜率统一**的对数映射：每 `45°` 恰好一个八度（倍率翻一倍）。

早期版本使用分段对数映射（减速侧 `ln 20`、加速侧 `ln 8`，各占 `135°`）。它把 `4.32` 个八度塞进减速侧、只把 `3` 个八度放进加速侧，于是 `0.5×` 落在 `-31.2°` 而 `2×` 落在 `+45°`，在 `1.0×` 处形成明显的斜率断点，旋钮手感与读数不成比例。统一斜率消除了这个断点。

### 6.1 角度到倍率

全程单一公式，`-180° ≤ θ ≤ +135°`：

```text
speed = 2 ^ (θ / 45)
```

### 6.2 倍率到角度

```text
θ = 45 × log2(speed)     再夹到 [-180°, +135°]
```

倍率先夹到契约范围 `[0.05, 8.0]`，算出角度后**还要再夹一次角度**：`0.05×` 位于 `1×` 下方 `4.32` 个八度，即 `-194.49°`，超出可达弧，因此固定夹到 `-180°`。

内部保留足够精度的浮点值；显示精度与输入步长独立于内部值。不得为了格式化显示而反向污染指针的实际倍率。

### 6.3 可达范围与端点

- 旋钮可达 `0.0625×–8.0×`，对应 `-180°–+135°`。
- 精确输入弹层仍可达契约下界 `0.05×`；此时指针停在最下方 `-180°`，读数显示 `0.05`。
- `aria-valuemin` 保持 `0.05`（而非 `0.0625`），否则精确输入把 `desiredSpeed` 设为 `0.05` 时会出现 `aria-valuenow < aria-valuemin`。

### 6.4 八度检查点

每个 `45°` 整数倍都精确落在一个八度上：

| 角度 | `-180°` | `-135°` | `-90°` | `-45°` | `0°` | `+45°` | `+90°` | `+135°` |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 倍率 | `0.0625×` | `0.125×` | `0.25×` | `0.5×` | `1×` | `2×` | `4×` | `8×`

`0.125×` 按两位小数显示为 `0.13`，`0.0625×` 显示为 `0.06`。

### 6.5 吸附点

吸附点集为 `0.1 / 0.2 / 0.25 / 0.4 / 0.5 / 1 / 2 / 4`，同时用于拖动中的 detent 和 `PageUp`/`PageDown` 跳转。它不等于八度检查点集：包含 `0.1 / 0.2 / 0.4` 这类实用挡位，且不含两端点（`0.0625×` 与 `8×` 由角度夹取本身精确命中，无需吸附）。

| 倍率 | 角度 |
| ---: | ---: |
| `0.10×` | `-149.487°` |
| `0.20×` | `-104.487°` |
| `0.25×` | `-90.0°` |
| `0.40×` | `-59.487°` |
| `0.50×` | `-45.0°` |
| `1.00×` | `0.0°` |
| `2.00×` | `+45.0°` |
| `4.00×` | `+90.0°` |

相邻吸附点的最小间隔是 `0.2×↔0.25×` 与 `0.4×↔0.5×` 的 `14.487°`，半间隔 `7.24°` 大于退出阈值 `6°`，因此各吸附点的捕获区互不重叠。**新增吸附点时必须保持这个不等式**，单元测试已将其锁定。

最终表盘不绘制可见刻度。倍率映射和吸附点保留在交互模型中，视觉上维持参考图的纯净时钟轮廓。

## 7. 指针交互

### 7.1 Pointer Events

- 鼠标、触摸和触控笔统一使用 Pointer Events。
- 交互起点可以是倍率分针、轴心或有效弧的透明命中区域；联动时针不单独接受命中。
- `pointerdown` 当帧立即给出按压反馈，并调用 `setPointerCapture(pointerId)`，保证指针移出表盘或窗口内元素边界后仍能完成拖动。
- 只允许当前捕获的 `pointerId` 更新该次手势；忽略其他并发指针。
- `pointerup`、`pointercancel` 和组件卸载时统一释放捕获并清理手势状态。
- 命中区域设置合适的 `touch-action`，防止表盘拖动被页面滚动手势抢占；页面其他区域仍保持正常滚动能力。
- 指针重新被抓取时，必须立刻停止尚未结束的吸附动画，从当前可见角度继续跟随。
- 从倍率分针或轴心开始抓取时记录 `grabOffset = currentPointerAngle - contactAngle`；后续移动保留这个角度偏移，避免首次移动时指针跳到触点方向。直接点击有效弧时不保留偏移，因为该动作的语义就是跳转到触点值。

### 7.2 拖动和点击

- 拖动期间不使用弹簧、缓动、延迟滤波或惯性。除吸附点的 detent 外（见 7.3），几何角度与输入位置保持 1:1。
- 使用约 `8–10` CSS 像素的位移迟滞区分点击与拖动；越过阈值后才进入 `dragging`，从而避免手指微抖把一次点击误判为拖动。
- 允许点击有效弧直接跳转到对应倍率。`pointerdown` 可显示候选位置，`pointerup` 且未越过拖动阈值时再提交；`pointercancel` 不提交。
- 不实现松手后继续旋转的惯性。
- 从屏幕坐标计算角度时，使用 SVG 坐标系中的中心点，不假设元素始终为固定像素尺寸。
- 对角度进行连续展开，并把每个拖动样本先绕回相对上一个已解析角度的**最短弧**，再夹到有效弧。这一步同时解决两件事：

  1. `atan2` 的返回区间是 `(-180°, +180°]`，正下方那一像素返回 `+180°` 而不是 `-180°`。在底部抓住指针时，`grabOffset` 会变成绕了整圈的 `-358°` 级数值；不绕回最短弧的话，后续每一帧的原始角度都远在 `-500°` 附近，指针会被永久锁死在端点上。
  2. 死区收窄到 `45°` 后，快速甩动更容易整帧跳过它。绕回最短弧后，落在死区里或穿过死区抵达的样本会被夹到它离开的那一侧端点，因此 `0.06×` 永远不会跨底部翻到 `8×`，反之亦然。想从一端到另一端，必须沿有效弧扫过 `1×`。

- 点击底部死区不改变倍率；键盘和精确输入不受死区命中限制，但仍受最小/最大值约束。
- 只有在 `@media (hover: hover) and (pointer: fine)` 成立时提供 hover 样式；触摸设备不伪造悬停状态。

### 7.3 吸附

吸附作用于 6.5 节的吸附点集 `0.1 / 0.2 / 0.25 / 0.4 / 0.5 / 1 / 2 / 4`，采用**拖动中实时 detent**：

- 拖动经过吸附点时立即把指针贴住该点并发出该倍率，给出可感知的“咔”住顿感。这是对 7.2 节 1:1 约定的唯一例外，为的是让常用倍率可以稳定停住。
- 进入阈值 `3.5°`，退出阈值 `6°`，用滞回避免在捕获区边界抖动。退出吸附时指针直接跳回真实角度（最多 `6°`），这是旋钮 detent 的标准做法；不做偏移吸收，以免破坏 `grabOffset` 模型。
- 退出一个吸附点时若立刻落进相邻吸附点的进入阈值，直接交接到相邻点，不经过自由角度。
- detent 判定必须是纯函数（输入为当前角度与上一帧持有的吸附点，输出为渲染角度、发出倍率和下一帧持有状态），组件只负责把状态穿过手势对象。`ui` 没有 jsdom/@testing-library，只有纯函数形态才可测。
- 松手时仍执行一次最终吸附兜底：拖动中已吸附时最终角度与当前角度相同，弹簧自然成为 no-op；点击跳转和键盘路径仍依赖它。
- 兜底弹簧应接近临界阻尼、无明显反弹；不能为了“有动画”而让精确数值越过目标。Motion 首版基线使用 `{ type: "spring", bounce: 0, duration: 0.28 }`，可在 `0.22–0.30s` 内校准，但必须保持零过冲。
- 弹簧的中间帧只服务于本地视觉，不逐帧发送 IPC。
- 保持吸附期间连续多帧是同一个倍率，必须只在倍率真正变化时才发送 IPC，不得每帧重复发送相同值。
- 用户在弹簧结束前再次按下，动画必须可立即打断。

### 7.4 rAF 合并与背压

浏览器侧：

1. `pointermove` 只保存最新样本。
2. 每个 `requestAnimationFrame` 最多消费一次最新样本、更新本地指针和 `desiredSpeed`。
3. 每个渲染帧最多向 C++ bridge 发送一次倍率更新。
4. `pointerup`、吸附完成或精确输入提交时强制发送最终值，不得被变化阈值漏掉。

Controller 侧还需执行第二级合并：

- 每个目标会话最多保留一条 in-flight 命令和一个“最新待发送值”槽位。
- 新值覆盖待发送槽位，不建立无限 FIFO。
- 当前 ACK 到达后，只发送此时最新的待发送值。

这种设计使快速来回拖动不会积累过量 WebView2 消息或命名管道请求，同时最终值仍然会被应用。

## 8. 键盘与精确输入

表盘可获得焦点，并实现完整的滑块键盘语义：

| 输入 | 行为 |
| --- | --- |
| `←` / `↓` | 角度减少 `1°` |
| `→` / `↑` | 角度增加 `1°` |
| `Shift` + 方向键 | 角度改变 `5°`，用于快速调节 |
| `Alt` + 方向键 | 角度改变约 `0.2°`，用于精细调节 |

| `Home` / `End` | 跳到 `0.0625×` / `8.0×`，即有效弧两端 |

键盘操作直接更新值，不附加装饰性的回弹或漂移动画。方向键是自由微调，不吸附；只有 `PageUp`/`PageDown` 走吸附点。单独的精确倍率输入使用 Base UI 的 Number Field/Field 等无样式可访问原语，要求：

- 接受有限数值并限制在 `0.05–8.0`。精确输入是到达 `0.05×–0.0625×` 之间的唯一途径。
- 明确显示 `×` 单位。
- `Enter` 或明确提交动作应用；非法、空值、`NaN`、无穷值不发送给 Controller。
- 错误文本与输入控件建立可访问性关联。
- 暂停时仍可修改“恢复后的倍率”，但 `appliedMode` 仍显示为暂停。

“恢复 1.0×”是独立按钮，并同时解除暂停。暂停按钮不把数值改成 `0×`；旋钮在暂停时仍显示恢复倍率。

## 9. 无障碍和 reduced motion

- 表盘提供可见标签并使用 `role="slider"`。
- 设置 `aria-valuemin="0.05"`、`aria-valuemax="8"`、当前 `aria-valuenow` 和易读的 `aria-valuetext`，例如“0.5 倍速度”。`aria-valuemin` 跟随契约下界 `0.05` 而不是旋钮下界 `0.0625`，因为精确输入能把 `desiredSpeed` 设到 `0.05`。
- 不用视觉角度作为唯一说明；精确数字输入是同等能力的替代操作。
- 焦点环在暗色背景和金色光晕上仍应清楚，且不能只依赖发光强度。
- 交互命中尺寸至少约 `44 × 44` CSS 像素。
- 连接、应用成功和失败可通过受节制的 live region 播报；拖动的每一帧不得触发屏幕阅读器播报。
- 状态必须同时由文字/图标表达，不能只依赖颜色。
- 在 Windows 高对比度或 `forced-colors` 下提供清晰的非发光轮廓回退。
- 在 `prefers-contrast: more` 下关闭弱对比度光效、增强核心轮廓与文字对比度。
- 如果后续引入半透明表面，在 `prefers-reduced-transparency: reduce` 下改用不透明背景；当前版本不以玻璃材质承载内容。
- 全局字体启用 `font-optical-sizing: auto`；按钮按压反馈使用约 `scale(.97)`、`100–160ms`，且不让键盘激活产生位移或回弹动画。

`prefers-reduced-motion: reduce` 下：

- 吸附立即定位，不运行弹簧。拖动中的 detent 本身就是瞬时定位，reduced motion 不改变它。
- NumberFlow 的数字滚动关闭。
- 面板、提示和状态切换使用即时变化或极短淡化。
- 不添加任何呼吸、脉冲、光晕漂移或颗粒运动。
- 拖动仍保持直接跟手；reduced motion 不是降低交互更新率。

## 10. 前端正交状态机

不要把所有组合塞进一个巨大枚举。以下状态区域相互正交，由一个集中式 reducer 协调即可；V1 不需要引入 Zustand。

```text
Controller:
  booting | ready | disconnected | resyncing | error

Target:
  none | selected | attaching | hooked | blocked | exited | error

Gesture:
  idle | dragging | editingNumber | snapping

Apply:
  unknown | synced | queued | inFlight | stalled | rejected

DesiredMode:
  running | paused

AppliedMode:
  unknown | running | paused
```

核心数据：

```text
desiredSpeed
appliedSpeed | null
desiredMode
appliedMode
controllerSessionId
targetGeneration
uiEpoch
lastIssuedUiSequence
lastAcceptedCommandSequence
lastClockRevision
pendingSince
lastKnownAppliedSpeed
lastError
```

### 10.1 关键状态规则

1. 没有已 Hook 目标时，`appliedSpeed = null`、`Apply = unknown`。可保留用户输入作为草稿，但不得称为已应用，也不得自动应用到下一个目标。
2. 开始拖动时立刻停止吸附动画，`Gesture = dragging`。指针和主要数值显示 `desiredSpeed`。
3. 倍率命令发送后进入 `queued` 或 `inFlight`；只有有效 ACK/STATUS 才能更新 `appliedSpeed`。
4. ACK 与最新 desired 不同并不等于 ACK 无效。只要它代表比当前已知 revision 更新的真实 DLL 状态，就更新 `appliedSpeed`，但继续显示“正在应用”，且绝不能把旧值写回 `desiredSpeed`。
5. 真正过期的确认必须丢弃，包括：

   - `controllerSessionId` 不匹配；
   - `targetGeneration` 不匹配；
   - `uiEpoch` 不匹配；
   - `commandSequence` 小于或等于已接受序号；
   - `clockRevision` 小于或等于已接受 revision；
   - 消息协议版本或类型不合法。

6. 超时不是成功也不是确定失败。进入 `stalled`，显示 DLL 暂时无响应，并由 Controller 发起 `GET_STATUS` 对账。
7. 对账结果与 desired 相同则进入 `synced`；不同则保留实际值并明确显示差异，不静默伪造同步。
8. 目标退出后进入 `Target = exited`，清空本目标的 applied 状态、序号和 generation。
9. 重复注入由 Controller 拒绝；前端显示既有会话或明确错误，不再创建第二套状态。
10. Hook 失效、协议错误或目标身份变化时停止发送倍率，进入错误/重同步路径。

### 10.2 失联状态

控制器与 Hook DLL 断开时：

- `Controller` 或目标连接状态进入 `disconnected`。
- 清空当前会话的 in-flight/queued 命令。
- `desiredSpeed` 重置为 `1.0`，`desiredMode = running`，避免重连时旧 UI 意图被误重放。
- `appliedSpeed` 设为未知；可把断开前值保存在只用于诊断的 `lastKnownAppliedSpeed`。
- 显示“已触发失联保护：1.0×，等待重新连接确认”。
- Hook DLL 本地立即连续重锚到 `1.0×`、解除暂停；该安全动作不能依赖 React 或 WebView2 仍然存活。

前端对每条入站消息执行 schema、范围、有限浮点数、会话身份和序号校验。React 不接触 DLL 路径、管道名、进程句柄或注入实现；只发送“选择目标”“设置倍率”“暂停”“恢复”“重置”等高层命令。

`desiredSpeed` 是 UI 意图，`appliedSpeed` 是 Controller/Hook 权威确认。时钟下方的状态行只使用三态文案（见 8.1）：未选目标、正常工作与明确失败；Unity 后端差异、`unverified`、`pending`/`stalled` 等运行细节保留在详情面板的详细状态列表中呈现，`pending` 持续 2 秒在详情中标记“Unity 暂未响应”，后续对账成功时自动恢复。

## 12. 异常状态与呈现

| 异常 | 前端行为 |
| --- | --- |
| IPC 延迟 | 保持本地拖动，显示目标值与最后已应用值，不堆积请求 |
| DLL 暂时无响应 | `stalled`，提供持续状态提示并触发对账，不宣称失败或成功 |
| 目标进程退出 | 清空 applied 状态、禁用控制、保留可读错误入口 |
| Hook 失效 | 停止发送新倍率；显示明确错误和失联保护说明 |
| Controller 重启 | 建立新 session，UI 回到 `1.0×`，先查询状态，不重放旧命令 |
| WebView2 页面失效 | Controller 尝试 RESET 并关闭目标会话；DLL 管道断开后自行恢复 `1.0×` |
| 重复注入 | 显示“已连接/已注入”或拒绝原因，不执行第二次注入 |
| 前后端状态不一致 | 同时显示 desired 与 applied，执行 GET_STATUS，对账前不隐藏差异 |
| 非法数值 | 本地阻止发送并在数字输入附近显示错误 |
| 过期 ACK | 丢弃且不触发 toast；只记录受限诊断信息 |
| 安全策略拒绝目标 | 显示持久、可阅读的拒绝原因，不提供绕过按钮 |
| `ACCESS_DENIED` | 仅用于真实的进程访问失败；不得把 TestApp 名称门禁或其他策略拒绝翻译成“权限不足” |
| `INTEGRITY_MISMATCH` | 说明目标以更高权限运行；这是唯一提供“以管理员身份重启 TimeTransle”的错误。用户取消后保持未连接且不循环弹 UAC |
| 完整性/保护/风险门禁拒绝 | 使用对应稳定错误和具体中文说明，不建议提权、关闭保护或规避风险 |

持久的安全错误不能只用 toast。Sonner 适合连接成功、应用失败、目标退出等短时通知；安全拒绝、失联和 Hook 故障还需要页面内的持久状态区域或对话框。

## 15. 前端阶段验收要点

在宣布首版前端“初步完成”前，至少满足：

- 参考图的完整双外环、四向连接桥、完整内环、中心轴和三层暖色光已用 SVG 重绘，没有嵌入原图。
- 倍率分针与联动时针位于独立旋转组；只有倍率分针映射 `desiredSpeed`，时针只按分针可见角度增量的 `1/12` 同帧跟随且不可单独操作。
- 核心线条随 SVG 等比缩放，双外环之间暗缝清楚；没有固定 CSS 像素粗描边，也没有仪表盘式可见刻度。
- 倍率读数使用正常网格布局位于表盘下方，在 `320/360/440` 下不与表盘、目标行或工具栏重叠。
- `0.0625× / 0.125× / 0.25× / 0.5× / 1× / 2× / 4× / 8×` 精确落在 `-180° / -135° / -90° / -45° / 0° / +45° / +90° / +135°`；每 `45°` 一个八度的统一斜率与全部吸附点角度通过单元测试。
- 相邻吸附点的最小间隔大于两倍退出阈值，捕获区互不重叠，且由单元测试锁定。
- 指针可以转到表盘正下方；从最下方快速甩到另一侧不会跨越死区突跳，最小值和最大值之间没有直接通路。
- 在底部抓住指针（`atan2` 在 `±180°` 翻面处）后仍能正常拖动，指针不会锁死在端点。
- 鼠标、触摸、触控笔均经过 Pointer Capture 路径；`pointercancel` 不会留下卡住的 dragging 状态。
- 抓住指针组时保留角度偏移，首次移动不会跳转；点击与拖动由 CSS 像素迟滞阈值明确区分。
- 缓慢扫过每个吸附点都有可感知的顿感，且 `0.2×↔0.25×`、`0.4×↔0.5×` 不互相抢吸。
- 除吸附点 detent 外拖动完全跟手，无延迟弹簧、无松手惯性；兜底吸附弹簧可立即打断。
- 保持吸附期间不重复发送相同倍率的 IPC。
- 键盘、精确输入、焦点样式和屏幕阅读器数值语义可用。
- reduced-motion 下没有弹簧和数字滚动。
- 每个浏览器渲染帧最多发送一条倍率变化；Controller 不形成无界 IPC 队列。
- `desiredSpeed` 与 `appliedSpeed` 在延迟、乱序 ACK、失联和重连期间始终可区分。
- 旧 session、旧 target generation 和旧 revision 的 ACK 不会覆盖当前状态。
- Controller/Hook 断开后，UI 重置为 `1.0×` 意图，DLL 独立执行即时恢复；重连后通过权威状态确认。
- 100%、150%、200% Windows 缩放下没有裁切、模糊或不可点击区域。
- 持续错误有页面内呈现，Sonner 不承担唯一错误载体。
- 完成 `$review-animations` 与 `$improve-animations` 指定的实施后审查流程。

阶段 1 的静态视觉原型不提前宣称满足上述功能验收。它必须明确标注“静态原型/尚未连接”，不渲染假的按钮、滑块语义或成功状态；只有接入真实 Pointer Events、状态机与 Controller 后，才进入本节的功能验收。
