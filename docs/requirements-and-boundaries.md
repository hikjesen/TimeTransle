# TimeTransle 产品需求与安全边界

> 文档状态：V1 产品基线；普通程序最小硬门禁与选择后自动连接流程已实现  
> 项目名称：TimeTransle  
> 目标平台：Windows 10/11  
> 本文用途：供后续 Codex 对话直接据此拆分任务、建立工程并实现。除非用户明确修改，本文中的“必须”“禁止”和已确认决策均视为约束，而非建议。

## 1. 产品目标

TimeTransle 是一个面向用户主动选择的 Windows 本地程序的时间倍率调节工具。它通过在目标进程内虚拟化单调时间，让依赖受支持 Windows 计时 API 的程序逻辑按指定倍率变慢、恢复、暂停或加速。

V1 的产品目标是：

- 用户明确选择一个已运行的目标进程后，TimeTransle 才可以执行安全检查和显式注入。
- 控制器展示目标、Hook、连接、期望倍率和实际应用倍率的真实状态。
- 在 `0.05×` 至 `8.0×` 范围内连续切换倍率，不使目标观察到时间跳变或明显倒退。
- 暂停作为独立状态提供，不将暂停伪装为旋钮上的 `0×`。
- 同时支持 32 位和 64 位普通桌面目标，但使用与目标同位数的注入助手和 Hook DLL。
- 硬门禁不满足时在首次写入前拒绝；硬门禁通过后报告真实的系统加载或 Hook 初始化结果。

TimeTransle 不承诺兼容所有程序，也不判断目标是否为游戏、单机、联网、竞技或带反作弊。目标自身的保护若阻止标准加载，应由真实的系统或 Hook 错误体现。

当前 SafetyPolicy 不接收或检查目标名称、发行商、商店、安装路径、窗口标题、联网状态或模块名称。TestApp32/64 继续作为确定性回归基准，但不拥有产品准入特权。

## 2. 术语与权威状态

- **Controller**：`TimeTransleController.exe`，负责目标选择、安全门禁、会话协调、WebView2 UI 和状态展示。
- **Injector**：与目标同位数的短生命周期注入助手。V1 需要 `TimeTransleInjector32.exe` 与 `TimeTransleInjector64.exe`。
- **Hook DLL**：目标进程中的 `TimeTransleHook32.dll` 或 `TimeTransleHook64.dll`。
- **TestApp**：用于受控验证的 32 位和 64 位测试程序。
- **初始速度**：固定指 `1.0×`，且 `paused=false`。
- **desiredSpeed**：用户当前希望使用的倍率。
- **appliedSpeed**：Hook DLL 已完成连续重锚并明确确认的实际倍率。
- **确认断开**：Hook DLL 的 IPC 客户端观察到管道关闭、`ERROR_BROKEN_PIPE`、EOF、服务器进程终止，或既定存活策略已经正式把连接状态转换为 `disconnected`。单次命令超时本身只表示状态未知，不得被 UI 误报为成功。
- **fail-closed**：无法可靠证明某项安全前提满足时，拒绝注入或停止后续操作。

Hook DLL 是目标进程内实际时钟状态的权威来源。Controller 负责协调命令，但不得在未收到 DLL 确认时把 `desiredSpeed` 当作 `appliedSpeed` 展示。

## 3. V1 支持矩阵

| 范围 | V1 支持 | 说明 |
| --- | --- | --- |
| 主机系统 | Windows 10/11 x64 | 普通交互式用户会话 |
| Controller | x64 | 托管 Win32 与 WebView2 |
| 目标架构 | x86/WOW64、x64 | 通过对应位数 Injector 和 Hook DLL |
| 目标类型 | 用户明确选择的、已运行的 x86/WOW64 或 x64 进程 | 不按用途、联网或游戏类别预判 |
| 目标启动方式 | 附加到已运行进程 | V1 不要求启动时注入或自动跟随子进程 |
| 时间倍率 | `0.05×` 至 `8.0×` | `1.0×` 为初始速度 |
| 暂停 | 支持 | 独立于配置倍率 |
| UI | Win32 Controller + WebView2 + React | SVG 时钟旋钮为主要交互 |
| IPC | Controller 与 Hook DLL 间的命名管道 | 必须带版本、会话和请求序号 |
| 管理员/更高完整性普通目标 | 支持显式权限匹配后附加 | 默认不提升；检测到目标更高时，由用户明确确认 Windows 标准 UAC 重启 Controller |
| PPL、受保护进程、关键系统进程 | 不支持 | 必须拒绝 |
| 联网、多人、竞技或带反作弊目标 | 不预分类 | 若目标自身阻止连接，返回真实失败 |
| ARM64 目标 | V1 不支持 | 发现后给出明确错误 |
| Microsoft Store/UWP、沙箱化或特殊容器目标 | V1 不保证支持 | 不预先拒绝；标准加载失败时返回真实结果 |

## 4. 核心功能需求

### 4.1 目标选择和生命周期

- `FR-TARGET-001`：Controller 必须枚举可检查的用户桌面进程，并由用户主动选择目标。
- `FR-TARGET-002`：在只读预检成功前，不得向目标写入内存、创建远程线程或加载 DLL。
- `FR-TARGET-003`：目标身份必须至少由 PID 和进程创建时间共同标识，避免 PID 重用导致误操作。
- `FR-TARGET-004`：Controller 必须判断目标架构，并只调用对应位数的 Injector 和 Hook DLL。
- `FR-TARGET-005`：Injector 只能加载产品目录中架构、协议版本和构建标识匹配的固定 Hook DLL，不接受来自 UI 的任意 DLL 路径。
- `FR-TARGET-006`：重复连接由 Hook 初始化的真实 `ALREADY_ATTACHED` 结果处理，不通过模块名称预扫描推断。
- `FR-TARGET-007`：目标进程退出时，Controller 必须终止该目标会话、清除实际应用状态、禁用相关 UI，并显示目标已退出。
- `FR-TARGET-008`：Controller 重启后必须先与 DLL 对账并读取权威状态，不得自动重放旧 UI 中的倍率命令。
- `FR-TARGET-009`：准入不得依赖目标名称、发行商、路径、商店、窗口标题、联网状态或模块名称。
- `FR-TARGET-010`：用户主动选择目标后必须由匹配架构 Injector 执行不申请 VM 写权限的 `--inspect-only`；UI 展示名称、PID、架构和检查结论，检查通过后 Controller 自动开始正式连接，不再要求第二次确认。
- `FR-TARGET-011`：正式连接必须重新检查全部硬门禁，然后使用标准 `LoadLibraryW + CreateRemoteThread`；不实现隐藏加载、manual map、驱动或保护绕过。
- `FR-TARGET-012`：目标完整性高于 Controller 时，不得直接写入；UI 应解释原因并允许用户明确触发 Windows 标准 `runas`/UAC 重启。提升后的 Controller 必须重新核验 `PID + 创建时间` 和全部门禁，不能复用提升前的“已通过”结论。
- `FR-TARGET-013`：用户取消 UAC、提升失败或提升后目标身份变化时，保持未连接并显示可恢复状态；不得循环弹出 UAC 或静默重试。
- `FR-TARGET-014`：不得维护游戏、反作弊、保护软件或联网程序名单；不得扫描 `risk_fragments` 或模块名，也不得预先拒绝 AppContainer、Dynamic Code、签名策略、CFG 等缓解策略。
- `FR-TARGET-015`：Controller 运行期间必须提供全局快捷键（修饰键为 `` ` ``，即 Esc 下方、Tab 上方的反引号键）：`` `+F1 `` 切换到 `1×`、`` `+F2 `` 切换到 `0.4×`、`` `+F3 `` 切换到 `2.5×`、`` `+Esc `` 切换窗口显示/隐藏。三个倍率键均为开关语义：激活时记录当前倍率为唯一检查点并取消暂停；再次按下同一键时恢复检查点并清除；处于特殊倍率时按下另一个倍率键则切换目标倍率并重记检查点（旧检查点作废）。已处于某个特殊倍率且没有检查点时（例如手动调整到该倍率），对应按键不得改变状态；用户手动修改倍率、切换目标、目标退出或连接状态离开 `hookedSynced` 时必须清除检查点。`Insert+F10/F11/F12` 组合自 0.1.5 起移除。
- `FR-TARGET-016`：进程选择列表必须展示每个进程可执行文件的原生图标（约 32×32 缩放显示），以辅助辨认进程。图标通过完整映像路径以 `SHGetFileInfoW` 提取、GDI+ 编码为 PNG data URL 传输；无法取得路径或图标的进程必须退化为名称首字母占位符，不得因此从列表中剔除条目。
- `FR-TARGET-017`：时钟下方的状态行只允许三种文案：未选择目标（含 Controller 启动中、未连接、目标已退出）显示「等待抉择」；已选目标且无失败时显示「进程名 正在翻译」；出现明确失败（需要管理员权限、预检失败、Hook 失效、命令被拒绝等）时显示「进程名 翻译失败」，悬停「翻译失败」时必须以深色浮窗展示失败原因，移开后消失。详细原因仍通过「!」按钮和详情面板提供。

### 4.2 倍率和暂停

- `FR-CLOCK-001`：可配置倍率范围固定为 `0.05×` 至 `8.0×`，输入必须是有限浮点数；`NaN`、无穷大和越界值必须拒绝。
- `FR-CLOCK-002`：初始状态必须是 `speed=1.0` 且 `paused=false`。
- `FR-CLOCK-003`：暂停是独立布尔状态。暂停时有效倍率为 `0`，但配置倍率仍保留为恢复后的倍率。
- `FR-CLOCK-004`：暂停期间修改倍率只更新恢复倍率，不推进虚拟时间。
- `FR-CLOCK-005`：“恢复 `1.0×`”操作必须同时设置配置倍率为 `1.0` 并解除暂停。
- `FR-CLOCK-006`：倍率变化和暂停/恢复必须使用连续重锚，不能把绝对真实时间直接乘以倍率。
- `FR-CLOCK-007`：标准虚拟时间模型为：

  ```text
  virtualNow = virtualAnchor + (realNow - realAnchor) × effectiveSpeed
  ```

- `FR-CLOCK-008`：改变倍率或暂停状态时，必须先使用原始时间源读取 `realNow`，再用旧状态计算边界处 `virtualNow`，随后更新 `realAnchor` 和 `virtualAnchor`，最后发布新倍率或暂停状态。
- `FR-CLOCK-009`：所有受支持时间 API 必须来自同一条连续的虚拟 elapsed timeline，不得各自独立漂移。
- `FR-CLOCK-010`：高频读取路径不得执行日志 I/O、内存分配或使用普通互斥锁；多线程连续读取不得出现明显时间倒退。

### 4.3 Controller 与 Hook DLL 断开连接

以下策略已经由用户确认，是不可留作配置项的 V1 默认行为：

- `FR-DISCONNECT-001`：Controller 与 Hook DLL 的连接一经**确认断开**，Hook DLL 必须在目标进程内立即自行切换回初始速度：`speed=1.0`、`paused=false`。
- `FR-DISCONNECT-002`：恢复必须执行一次连续重锚：以断开时刻的当前虚拟时间作为新的虚拟锚点，以原始现实时间作为新的现实锚点，然后发布 `1.0×` 和非暂停状态。目标不得观察到恢复点上的时间跳变或倒退。
- `FR-DISCONNECT-003`：不得保留最后倍率，不得等待宽限期，不得等待重连，也不得依赖 Controller 在断开后发送 `RESET`。
- `FR-DISCONNECT-004`：该恢复逻辑必须完全位于 Hook DLL 本地，因此 Controller 崩溃、被终止或管道意外关闭时同样生效。
- `FR-DISCONNECT-005`：恢复动作完成后，DLL 的权威状态和后续重新连接时报告的状态都必须是 `1.0×`、`paused=false`。
- `FR-DISCONNECT-006`：命令 ACK 超时但管道仍存在时，Controller 必须把应用状态显示为未知并进行状态对账；一旦 DLL 自身正式判定连接已断开，就必须立即执行上述本地恢复。

### 4.4 命令和状态一致性

- `FR-STATE-001`：前端必须分别保存和展示 `desiredSpeed` 与 `appliedSpeed`。
- `FR-STATE-002`：每条改变时钟状态的请求必须携带递增序号、Controller 会话标识和目标会话/代次标识。
- `FR-STATE-003`：DLL 必须在完成连续重锚后再 ACK；ACK 必须包含实际倍率、暂停状态和时钟 revision。
- `FR-STATE-004`：前端和 Controller 必须忽略旧会话、旧目标代次及已过期序号的 ACK。
- `FR-STATE-005`：高频拖动不得形成无界 IPC 队列。Controller 至多保留一条在途命令和一个“最新待发送值”，新值覆盖未发送的旧值。
- `FR-STATE-006`：DLL 暂时无响应、目标退出、Hook 失效、Controller 重启和 IPC 状态未知都必须有独立且诚实的 UI 状态，不得假装设置成功。

## 5. Hook API 范围

### 5.1 V1 必须 Hook

- `QueryPerformanceCounter`
- `GetTickCount`
- `GetTickCount64`
- `timeGetTime`

### 5.2 V1 明确不得 Hook

- `QueryPerformanceFrequency`
- `Sleep`
- `SleepEx`
- `WaitForSingleObject` 及其 Ex 变体
- `WaitForMultipleObjects` 及其变体
- `MsgWaitForMultipleObjectsEx`
- 网络连接、请求或套接字超时函数
- 系统日期、日历和墙上时钟函数
- 音频时钟与媒体播放速率函数

### 5.3 API 语义要求

- `QueryPerformanceFrequency` 必须保持系统原始结果。
- `QueryPerformanceCounter` 必须使用原始 trampoline 获取现实时间，禁止递归调用已 Hook 入口。
- `GetTickCount64`、`GetTickCount` 和 `timeGetTime` 必须由统一虚拟 elapsed timeline 换算为毫秒。
- `GetTickCount` 与 `timeGetTime` 的 32 位回绕行为必须与 Windows 自然回绕兼容，不得通过饱和或额外纠正改变其语义。
- 每个 Hook 必须保存和调用合法原始 trampoline。
- Hook 创建或启用任一环节失败时，必须禁用并移除本次已安装的全部 Hook，再返回明确错误。
- `DLL_PROCESS_ATTACH` 只允许最小化、加载器锁安全的工作；耗时初始化、IPC 建立和 Hook 安装必须移出 `DllMain`。
- 停止会话时必须先恢复初始速度，再停止接收新命令、禁用 Hook、等待在途 detour 安全退出，最后清理 IPC 和 Hook 资源。
- V1 可以采用“逻辑停用后 DLL 作为 inert module 驻留至目标退出”的安全生命周期；不得为了热卸载而冒险释放仍可能被执行的代码。

## 6. 明确禁止项

TimeTransle 及其构建、测试、诊断和发布工具均禁止实现或尝试实现：

- 权限提升漏洞利用、令牌窃取、UAC 绕过、静默提权或在用户未明确选择高完整性目标时请求管理员权限。用户明确确认的 Windows 标准 UAC 重启属于支持路径。
- 内核驱动、内核修改、内核回调规避或直接操作受保护内存。
- 受保护进程/PPL、关键系统进程或进程缓解策略绕过。
- 反作弊、反注入、完整性校验或安全产品的规避、禁用、欺骗或隐藏。
- 隐藏 DLL、manual map、反射式加载、PEB/LDR 链摘除、隐藏线程、隐藏句柄、进程伪装或其他隐蔽注入行为。
- 自动选择目标、后台静默注入、开机驻留、无用户确认地跟随子进程。
- Hook 网络、认证、系统日期时间、文件完整性或遥测函数来扩大兼容性。
- 绕过目标自身施加的访问、签名、动态代码、PPL 或其他保护失败。
- 在日志或 UI 中宣称可以绕过、不会被检测或兼容所有游戏。

## 7. 安全门禁与 fail-closed 行为

硬性门禁必须在任何写入目标进程或远程加载动作之前完成。顺序如下：

1. 由匹配架构 Injector 使用只读 `--inspect-only`，以 `PROCESS_QUERY_LIMITED_INFORMATION` 打开目标。
2. 验证目标 PID 与创建时间仍与用户所选目标一致。
3. 判断目标与 Injector 架构是否受支持且匹配。
4. 比较 Controller 与目标的完整性级别；目标更高时停止当前连接流程，并允许用户明确确认标准 UAC 重启。提升后的 Controller 从稳定身份检查开始重新执行全部门禁。
5. 检查目标是否为 PPL、Windows 受保护进程或关键系统进程。
6. 检查产品目录中固定 Hook DLL 的架构、构建 ID 和版本身份。
7. 向用户展示目标名称、PID、架构和检查结论，再要求明确触发。
8. 正式连接重新执行以上检查，并直接尝试标准加载；重复连接由 Hook 初始化结果判断。

目标可执行文件名、发行商、商店、安装路径、窗口标题、已加载模块名称和联网状态都不是安全证据，也不得影响准入。

必须拒绝的情况包括但不限于：

- 无法取得完成某项必要检查的最小查询权限。
- 必要硬门禁无法查询、访问被拒绝、数据不一致或在检查中途目标身份发生变化。
- 目标完整性级别高于当前 Controller，且用户尚未完成标准 UAC 权限匹配、取消提升或提升失败。此状态只阻止当前连接，不把目标永久标记为不支持。
- 目标为 PPL、受保护进程、关键系统进程或明确排除的系统组件。
- 架构不支持或与所选 Injector/Hook DLL 不匹配。
- DLL 路径、签名/哈希、构建 ID 或协议版本不符合产品预期。

拒绝后必须：

- 不执行写入目标、远程线程或 DLL 加载。
- 显示具体、可操作但不包含绕过建议的错误。
- 记录结构化错误码。
- 不提供绕过保护的强制连接。只允许在原始错误明确为 `INTEGRITY_MISMATCH` 时提供“以管理员身份重启 TimeTransle”按钮。

AppContainer、缓解策略或目标自身保护不属于预先拒绝项；它们若阻止标准加载或 Hook，应返回真实的 `ACCESS_DENIED`、`DLL_LOAD_FAILED`、`HOOK_CREATE_FAILED` 等结果。

## 8. TestApp 和测试要求

### 8.1 TimeTransleTestApp 显示内容

32 位和 64 位 TestApp 都必须显示：

- 由 `QueryPerformanceCounter` 与原始 `QueryPerformanceFrequency` 推算的当前 elapsed time。
- `GetTickCount`。
- `GetTickCount64`。
- `timeGetTime`。
- 每帧 `deltaTime`。
- 一个严格根据 `deltaTime` 移动的可视测试对象。
- 当前渲染 FPS。
- 根据受支持时间源与独立现实参考推算的当前检测倍率。
- 当前 Hook/IPC 状态以及是否暂停。

TestApp 只用于本项目的受控验证，不得包含绕过安全门禁的测试入口。

TestApp 是确定性和故障注入的必要回归基准，但不是普通程序支持的唯一验收对象。兼容性测试以用户主动选择的自有或明确授权程序记录实际成功、部分生效或真实失败，不为特定程序添加放行或拒绝特例。

### 8.2 最低验收用例

- `TEST-001`：`0.5×` 下，现实 `10s` 对应虚拟 `5.0s ± 0.1s`。
- `TEST-002`：`2.0×` 下，现实 `5s` 对应虚拟 `10.0s ± 0.1s`。
- `TEST-003`：从 `1.0×` 切换到 `0.5×` 时，切换边界无可见跳变或倒退。
- `TEST-004`：从 `0.5×` 切换到 `2.0×` 时，切换边界无可见跳变或倒退。
- `TEST-005`：暂停冻结虚拟 elapsed time；恢复时从冻结点连续推进。
- `TEST-006`：暂停期间改变恢复倍率不会推进虚拟时间。
- `TEST-007`：多线程高频读取时，每个读取线程观察到的时间不明显倒退。
- `TEST-008`：四个受支持 API 的累计 elapsed 基本一致；连续 `10s` 测量的相互差异目标不超过 `20ms`。
- `TEST-009`：32 位 `GetTickCount` 和 `timeGetTime` 的回绕测试保持无符号 DWORD 语义。
- `TEST-010`：重复安装、失败回滚和逻辑停用 Hook 不崩溃；逻辑生命周期循环目标为至少 100 次。
- `TEST-011`：任一 Hook 安装失败时，本次已安装 Hook 全部回滚，目标继续以原始时间运行。
- `TEST-012`：Controller 正常退出、崩溃、被强制终止、命名管道被关闭和服务器消失时，DLL 均立即连续重锚到 `1.0×`、`paused=false`。
- `TEST-013`：断线恢复测试不得依赖 Controller 发送 `RESET`，不得等待宽限期，不得保留最后倍率。
- `TEST-014`：目标退出后 Controller 正确结束会话并清除 `appliedSpeed`。
- `TEST-015`：快速往返拖动、ACK 乱序和 IPC 延迟下，过期确认不会覆盖新状态，健康连接下最终 `desiredSpeed` 与 `appliedSpeed` 一致。
- `TEST-016`：高频拖动时 IPC 队列保持有界，不会积累每个 pointer event。
- `TEST-017`：重复选择已 Hook 目标不会重复加载 DLL。
- `TEST-018`：较低完整性 Controller 面对管理员权限测试目标时，在首次写入前停止并返回 `INTEGRITY_MISMATCH`；用户取消 UAC 时不写入、不重复提示；用户明确确认 UAC 重启后，提升版 Controller 重新枚举、重新预检，并仅在新预检通过后自动连接。
- `TEST-019`：PPL、关键系统目标、架构不匹配和身份变化始终在首次写入前被拒绝；加载 `AntiCheatFixture.dll` 以及启用 Dynamic Code、签名、CFG 缓解策略的夹具不因名称或策略被预先拒绝。
- `TEST-020`：选择普通 x86/x64 夹具后无需打开详情菜单或再次点击即可完成预检和连接；三组全局快捷键遵守倍率保存、自然 `1×` 无操作、会话清理和窗口聚焦语义。

对纯 VirtualClock 的确定性测试应使用可注入的假现实时钟，至少覆盖有限值校验、极限倍率、连续重锚、暂停、恢复、断线恢复、整数换算、溢出边界和并发快照一致性。

## 9. 兼容性限制与用户可见说明

即使所有 Hook 都安装成功，以下目标也可能不受影响或只部分受影响：

- Unity Mono 目标在运行时具备标准 `UnityEngine.Time` 内部调用时，TimeTransle 使用 `Time.timeScale` 后端；倍率与游戏自身 `timeScale` 乘算，读取时对游戏隐藏外部倍率。
- Unity Mono 后端不调整 `fixedDeltaTime`，也不缩放 `unscaledDeltaTime`、音频采样时钟或网络时间。
- Unity IL2CPP 暂不属于本版本的引擎适配范围；它仍只能尝试通用 Win32 时钟后端。

- 直接读取 `RDTSC/RDTSCP` 或其他未 Hook 硬件时间源的程序。
- 使用引擎私有计时器、共享内存时钟或自定义系统调用的程序。
- 使用完全固定物理步长且不依赖被 Hook API 调度逻辑的程序。
- 由服务器决定逻辑时间的程序；本地时钟调整可能不生效。
- 动画、物理、AI、视频和音频分别使用不同时间源的程序。
- 预渲染视频和按真实采样时钟播放的音频；V1 不进行重采样或变调/保调处理。
- 使用等待超时推进逻辑的程序；V1 不缩放 `Sleep` 或 Wait API。
- 使用系统日期/日历时间推进逻辑的程序；V1 不改变墙上时钟。
- 动态完整性校验、代码保护、反注入或进程缓解策略阻止常规 DLL 加载的程序。
- 多进程游戏中逻辑位于另一个未选择进程的情况；V1 不自动跟随或批量注入。

UI 必须把“不兼容或未生效”与“设置命令失败”区分开。不得用限制帧率或限制 CPU 作为时间倍率的替代方案，因为它们不能保证按比例改变目标的逻辑时间。

## 10. 日志、诊断和隐私

- 日志必须是本地 JSONL，只记录时间、组件、阶段、真实 API/Hook 结果和稳定错误码。
- 默认日志不得包含用户名、主目录、完整可执行文件路径、命令行参数、环境变量、窗口标题、游戏账号、文档路径或内存内容。
- 日志不记录目标进程名、PID、完整路径、窗口标题或命令行。
- 命名管道随机标识、会话令牌、校验材料、原始 IPC payload 和可能充当凭据的值不得写入日志。
- 日志不得记录被 Hook API 的逐次调用；高频 Hook 路径不得进行任何日志 I/O。
- 安全门禁日志必须说明“哪项检查失败”和稳定错误码，但不得给出规避或绕过步骤。
- 日志固定在 `%LOCALAPPDATA%\TimeTransle\logs`，单文件上限 `2 MiB`，保留当前文件及 4 份轮转文件。
- V1 不应默认上传遥测、崩溃转储或日志。任何未来上传功能都必须单独取得用户明确同意并先展示数据范围。
- 崩溃转储可能包含目标进程隐私数据，V1 不得自动抓取或上传目标进程转储。

## 11. 完成定义

TimeTransle V1 只有在下列条件同时成立时，才可声明核心时间控制功能完成：

- 32 位和 64 位自有 TestApp 都通过全部核心倍率、暂停、并发、API 一致性和断线恢复测试。
- 至少一个非 TestApp 命名的 x86 程序和一个非 TestApp 命名的 x64 程序通过目标确认、全部硬门禁、连接、倍率、暂停、恢复和断连保护验收。
- 所有门禁拒绝场景都证明发生在首次写入目标之前。
- Controller 或管道异常消失时，Hook DLL 无需任何 Controller 命令即可立即、连续恢复 `1.0×` 且解除暂停。
- UI 始终区分期望状态、实际确认状态和未知状态。
- Hook 部分失败可完整回滚，目标不会停留在部分虚拟化状态。
- 产品文档清楚说明兼容性限制、标准加载边界和不承诺所有程序都能连接。
- 前端表盘与倍率不重叠，线宽和光晕符合参考图的细线层级，倍率分针与机械联动时针彼此独立，并通过 `320/360/440` 与 100/150/200% DPI 验收。
- 错误分类能区分真实访问被拒绝、完整性不匹配、目标身份/架构变化、DLL 加载和 Hook 初始化失败；本地结构化诊断日志可定位失败阶段且不泄露敏感信息。

后续实现如需改变本文中的支持范围、禁止项、断线行为或 fail-closed 原则，必须先取得用户明确确认并同步修改本文；不得仅在代码中静默改变。
